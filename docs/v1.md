# What v1 means

v1 is a promise about applications, not a count of features:

> **An application built on v1 does not need a major refactor for the foreseeable future. Later releases
> add functionality to the abstractions v1 already has.**

So v1 is reached when the abstractions stop moving, not when the list of capabilities is long. A capability
that is missing at v1 is fine if the abstraction it will attach to is already there. An abstraction that is
still being drawn is not fine, however much works on top of it. [status.html](status.html) grades where each
capability *lives*; this page grades whether the shape it lives in is *final*. The two are different
questions, and only the second decides the version number.

## What counts as breaking

A change is breaking if an application that compiled, passed and behaved correctly on v1.x would not on
v1.x+1 **without the application's author touching it**. That is wider than a removed method:

- **A new compile error is a breaking change.** The processor's whole job is to move failures leftward, so
  every new check is a way to break a build that was accepted yesterday. A check may land after v1 only if
  it rejects something that was already a bug. Anything else lands before v1, or behind an opt-in.
- **A different resolution is a breaking change.** Which provider satisfies a parameter, which phase a part
  is built in, what a generated wiring is named, what a `null` provider does: an application depends on
  these without ever writing them.
- **A different lifecycle order is a breaking change.** `Phase` and `FrameStage` are contracts. Adding a
  phase between two existing ones moves every part built around it.
- **The generated project is application code.** Once `vexel-desktop` has produced a project, the
  template is a promise about what that project keeps compiling against. A change to the builder's public
  API is also a change `mainframe` compiles against.
- **The wire protocol is an interface.** A script that drove the application on 1.0 must still drive it.
  New verbs are additive. A verb's replies are not.

Additive means: a new method with a default, a new annotation attribute with a default, a new starter, a
new verb, a new `Shell` accessor, a new module. It never means a new obligation on existing code.

## The contract surface

Six surfaces, and v1 freezes each. The state of each is in [status.html](status.html#v1-ledger).

| Surface | What is promised |
| --- | --- |
| **The annotations** (`-api`) | Every annotation, attribute and default; and the **processor semantics** behind them, which are the larger half: type matching, phase inference, `@Default` and back-off, generated names, the checks that exist |
| **`Shell` and the phases** | Every accessor, the phase each is legal in, the order parts are built in, and what a wiring may do at each |
| **The component model** | How a component declares its lane, its channels and its loss class; what may cross a lane; what a wedged component does to the rest. `Lanes` and `Placement` are the threads and mailboxes. The declaration side is not built |
| **The build shape** | Module coordinates, starters, the BOM, the reachability metadata an application inherits, and what `new vexel-desktop` writes |
| **The launch surface** | `Launch`, `FRAMEWORK_KEYS`, the reserved keys, `--automation` and `--profile`, exit behaviour, what is reported when a capability is dropped |
| **The wire protocol** | The automation line protocol: framing, `ok` and `err`, the verbs and their replies |

**A seventh surface is not the framework's, and bounds all six.** `Shell` hands over `Gui`, `GuiApp`,
`KronoGui`, `Modals`, `TitleBar`, `WindowMemory`, `Settings`, `CloseRequest` and `Atchung`, so an
application holds `vexelray-gui`'s types directly. v1 cannot be more stable than they are. Either those
repos freeze what `Shell` exposes, or `Shell` stops exposing it. That is a decision, not a task, and it is
in [TODO.md](TODO.md).

## When an abstraction is frozen

An abstraction is ready to freeze when all four hold. Anything short of that is *experimental*, however
well it works.

1. **It has more than one witness.** The framework's own method, *one component is not a census*, applies
   to the framework itself. Today one generated application validates the abstractions, because the three
   ported ones were deleted on purpose. Freezing something drawn from one shape freezes that shape's
   accidents.
2. **Its semantics are decided in writing.** Not "works", but "in this case it does this, and here is why"
   in [architecture.md](architecture.md). The open ones (exact-type matching, a `null` provider) are cheap
   today and a breaking change afterwards.
3. **Its extension points are named.** For each thing v1 leaves out, the abstraction it will attach to
   exists already. That is the extension test, below.
4. **No entry under *Blocks v1* in TODO.md names it.**

## The extension test

The bar is "future releases add to the abstractions we have". So for every capability v1 leaves out, name
the seam it will use. If there isn't one, the seam is a v1 item and the capability is not.

| Left out of v1 | The seam it attaches to | Does the seam exist? |
| --- | --- | --- |
| Diagnostics, `--profile` | A starter plus `@ConditionalOnType`; `atchung-probe` | Yes. The module's *name* is undecided, and it is Maven coordinates |
| Framework SDF vocabulary | A `@Provides` and a placed component | Only once the component model is final |
| elektro-Q, cross-process actors | The channel declaration | **No.** The declaration is unbuilt |
| Simulation vocabulary | `FrameStage.APP`, and a placed component | Partly. `APP` is an empty slot by design |
| Reactive automation, macros, extensions | The channel declaration | **No.** The same seam |
| A second automation socket | `Driver.open(shell, gui, controls, offset)` | Yes; additive |
| Supervision | Per-component `Overrun`, the wiring | The hooks are not surfaced; the contract a component owes its supervisor is undecided |
| A BOM, more starters | `@Default` and `@VexelApp` naming | One starter exists; a second is the test of the shape |

Two rows fail. That is why the concurrency work sits ahead of everything else.

## How to get there

In this order, because each step decides what the next bakes in:

1. **Finish the component model.** The channel declaration, the colour rule's copier and capture halves,
   the message-graph checks, supervision, and the completion path for work that outlasts a frame. It
   reshapes how every component is written, and it is where new compile errors come from.
2. **Decide the semantics nobody has argued.** Exact-type matching, `null` providers, which defaults are
   replaceable, whether a new `Phase` is ever additive, and how a new processor check is allowed to land.
3. **Settle the boundary with the siblings.** What `Shell` exposes of `vexelray-gui`, and the upstream bus
   that admits one tree. Then the composition root: `GuiApp` and `VexelEngine`.
4. **Add witnesses.** Two or three generated applications with deliberately different shapes: several
   windows, component-heavy, long-running with nothing to settle. Each is expected to find something. What
   they find is written up, as the ports were.
5. **The build shape.** A second starter, the BOM, and aggregated reachability metadata, once the
   abstractions they package have stopped moving.
6. **Freeze.** Walk the whole public surface. Anything that would be renamed or restructured today is
   fixed first. Anything not yet frozen is marked. Then cut 1.0.

Until then releases are 0.x, and 0.x says what it means: the shape may still move.

## How the surface is marked

There is no marker in the source today, and the version is `0.1.0-SNAPSHOT`. Before the freeze, each public
type is either frozen or experimental, and a reader can tell which without asking. The mechanism is
undecided; it is a TODO. It must be a `CLASS`-retention annotation or a Javadoc tag, since nothing here
reflects.

## What v1 is not

Not feature-complete. Rendering vocabulary, the game-engine half, cross-process actors and the diagnostics
module can all arrive after v1, each behind a seam the extension test names. It is also not a claim that
the design is right, only that we will stop changing it under people.
